## 1. プロジェクトの概要

**1.1.0 でプラグインの名前を「OBS Harmonizer (obs-harmonizer)」から「Scene Relight (obs-scene-relight)」に変えた。** 変えたのは表示名・ビルドの成果物の名前・インストール先。リポジトリ名（`yub4-arema/obs-harmonizer`）、フィルターの内部 ID（`obs_harmonizer_filter`、`obs_harmonizer_finish_filter`）、ソースやシェーダーのファイル名、表示文字列のキー（`Harmonizer.*`）は変えていない（内部 ID を変えると、保存済みのシーンからフィルターが消える）。以下の文中の「Harmonizer」は、前景に掛けるフィルターのこと。

OBS Studio 用のフィルター・プラグイン（C + HLSL 風 `.effect`、GPU のみ、CPU 読み戻しなし）。

- **Harmonizer（背景になじませる）**: 前景（立ち絵）に掛ける。背景ソースを指定すると、背景の光の色・明るさ・コントラスト・陰影・縁の光を前景に反映する。
- **Finish（仕上げ：撮影処理）**: シーンやグループに掛ける。網点・グレイン・光漏れ・ビネット・色収差・周辺ボケ・グロー・レンズフレア。
- **Lens Blur（背景ぼかし）**: 背景のソースに掛ける。背景だけを円盤状にぼかし、明るい点は玉ボケにする。
- 参照実装（numpy）: `tools/reference.py`。シェーダーと同じ式で、見た目の検討に使う。
- ビルドは obs-plugintemplate 準拠。Linux でのビルドとテストの手順は 6 節。

主なファイル:

| パス | 役割 |
| --- | --- |
| `src/harmonizer-filter.c` | Harmonizer 本体（プロパティ定義、前処理パスの駆動） |
| `src/finish-filter.c` | Finish 本体（網点・グレイン・光漏れ・周辺減光・色収差・周辺ボケ・グロー・レンズフレア） |
| `src/lensblur-filter.c` | 背景ぼかし（Lens Blur）本体 |
| `data/effects/harmonizer.effect` | 本体シェーダー（**参照実装と同じ式**） |
| `data/effects/finish.effect` / `lensblur.effect` | 仕上げのシェーダー / 背景ぼかしのシェーダー |
| `data/effects/harmonizer-prep.effect` | 前処理（背景を 256x144 → 32x18 に畳み、統計 6x1、環境光マップ、前景統計） |
| `data/locale/{ja-JP,en-US}.ini` | 表示文字列 |
| `tools/reference.py` | 参照実装 |
| `tests/headless_test.py` | OBS をヘッドレスで動かす実機テスト（Linux、要 obs-studio / xvfb） |

調整できるパラメータ（現在の初期値。v3）: `strength=1.0`, `tint=0.8`, `exposure=0.65`, `contrast=0.0`, `shadow_tint=0.6`, `shading=1.0`, `shading_spread=4.0`, `rim=0.4`, `rim_width=4.0`, `rim_dir=0.85`、手置きライト 2 枠。第 1 回の評価（2.2〜2.4 節）は旧方式・旧初期値でのもの。

### 2.4 原因の分析（利用者の仮説＋コード読み）

利用者の仮説: 「背景をそのまま参照するせいで、川などの色がそのまま反映され、立体感・距離感が崩れる」。コードを読んで、仮説と整合する原因を 3 つ特定した（`data/effects/harmonizer.effect` の現行版）。

1. **明るさ追従**: `g = target_m * pow(g / fg_m, s)` を RGB 各チャンネルに掛けている。`fg_m` は前景の平均輝度で、黒い制服が平均を押し下げるため、明るい背景では倍率が過大になり、明るい髪が白飛びする。倍率に上限もない。
2. **自動陰影**: `shade = pow(rel, shading*0.8) * (1 + (e/eL - 1) * 0.5 * shading)`。`e` は「前景の背後にある背景の色」で、**彩度の制限なし**。川の水色や木の緑が前景に直接乗る（＝写り込み）。`rel` の範囲も 0.25〜2.5 と広く、背景の暗い木陰の前では前景が大きく暗くなる。
3. **光の色・縁の光**: 彩度上限 0.45（光の色）と制限なし（縁の光 `e/eL`）。青空や川の色に引っ張られる。

## 3. 現在の作業状態（v3。コミット・プッシュ済み）

利用者の目標: **どんな背景でも、立ち絵やキャラが「そこにいる」感じを出す**。利用者の好み: 夜、はっきりした光源の下、影の中のように、光の状況がはっきりしている場面は写実的に効いているのが好き。

v2（前回の案）は見比べた結果、不採用にした。昼は肌が青白くなり（光の色を平均寄りの色から取っていたため空の青を拾う）、夜はほとんど変化しなかった。

**v3 を参照実装（`tools/reference.py` の `harmonize`）とシェーダーの両方に入れた**。旧方式は参照実装にだけ `harmonize_legacy`（`prm['legacy']=True`）として残してある。

v3 の考え方（「その場の光で照らされた前景」を作る）:

1. **光の色**: 明るい場面では背景の「白」（チャンネルごとの 12 乗平均。昼なら雲の白）を光の色とみなす。昼の空や川の青は光の色とみなさないので、**昼はほぼ何もしない**。暗い場面（夜）と、暖色のかぶり（赤 > 緑 > 青＝夕日）は、明るい側の平均の色を使う。暖色は「白」まで暖色のときだけ認める（紅葉や赤い屋台のように、昼の光の下で物が暖色なだけの場面を除く）。青緑の光で肌が土気色にならないよう、赤を減らす下限（`RED_MIN` 0.8）がある。色を乗せて 1 を超えた分は、輝度を保ったまま彩度を下げて収める。
2. **明るさ**: 背景の明るい側の輝度が低いほど（夜）、前景を暗くする（下限 0.3 倍）。明るい場面では変えない。旧方式の「前景の平均に対する倍率」はやめた（髪の白飛びの原因）。
3. **空気の色**: 暗い所（黒い服・髪）に、背景の暗部の色を加える。明るい背景で黒が白っぽく浮かないよう、輝度に上限（`AIR_MAX`）があり、明るい場面（昼・夕方）では 1 割まで弱める。
4. **自動陰影**: 背後がまわりより暗ければ影に入る（比 0.35〜1 を指数 0.6×明るさの倍率で。暗い場面では弱まる）。
5. **光源**: 背景の平均の 2 倍より明るい所を光源とみなし、その超過分を色ごと残してぼかした「光源マップ」を作る。前景の各点は、背後の光源マップの強さに応じて、**光源の色のまま**（彩度の上限 0.5）照らされる（全体にうっすら＋光源を向いた側の面を強く。面は alpha の勾配を前景の高さの 6% の半径で取った太い帯）。明るい場面（昼）では空や日なたを光源と取り違えるので、場面の明るさに応じて消す（`night`）。
6. **縁の光**: 背後がまわりの 1.2〜2.2 倍以上明るい側の縁だけ、その場の光の色で光らせる。光源の近くでは光源の色で強く。背景の回り込みは、暗い色（黒髪・黒い服）の上では白くぼやけて見えるので 3 割まで弱める。
7. コントラストの追従は残したが初期値 0。手置きの光と影は旧方式と同じ。

初期値: `tint=0.8`, `exposure=0.65`, `contrast=0.0`, `shadow_tint=0.6`, `shading=1.0`, `rim=0.4`（他は変更なし）。

移植で変えた所:

- `data/effects/harmonizer-prep.effect`: 統計を 4x1 → **6x1** に（4: その場の白、5: その場の黒）。光源マップ用の `SrcH` を追加。
- `src/harmonizer-filter.c`: 統計の描画先を 6x1 に、光源マップ（`src_h` と `src` のピンポン）を追加、初期値を上のとおりに。
- `data/effects/harmonizer.effect`: 本体を v3 に。
- `data/locale/*.ini`、`README.md`: 項目名と説明を v3 に合わせた。
- `tools/reference.py` の `blur_grid` は、シェーダーと同じ ±12 タップにした（以前は 2σ で打ち切っていて、光源マップの裾で差が出た）。

**実機テストは通過**（OBS 30.0.2、`xvfb-run -a python3 tests/headless_test.py build_x86_64`。全項目 ok。OBS の出力と参照実装の差は平均 0.004〜0.005）。テストに「夜の光源が近い側から前景を照らす」確認を追加した。

### 3.3 真っ暗な場面の修正（1.1.0 の後）

利用者の報告: 灯籠と提灯の並ぶ夜の参道（AI 生成の背景）で、キャラが明るすぎる。利用者の理想は「全体は暗いが、灯りの光でその方向から照らされて見える」。

- 原因は 2 つ。(1) 暗くする量を `hl`（明るい所に重みを寄せた平均）だけで決めていて、灯りに引っ張られて `hl` = 0.26（神社の夜と同程度）になった。背景全体の平均の輝度は 0.014 で、これまでの夜の背景（0.05〜0.23）よりずっと暗い。(2) 光源の強さを背景の平均で割っていたため、平均がとても暗いと光源の値が膨らみ、前景全体が 1.6〜2.8 倍に照らされていた。
- 修正（参照実装とシェーダーの両方）:
  - 明るさの倍率に `(mean_lp / MEAN_REF)^2.2`（`MEAN_REF` 0.22）を掛ける。下限 `GAIN_MIN` は 0.3 → 0.1。
  - 真っ暗な場面では、光の色を背景の平均の色（彩度の上限 `AMB_LIMIT` 0.3）に寄せる。灯りの暖色は光源の光としてだけ乗る。
  - 光源の強さを割る基準に下限 `SOURCE_FLOOR` 0.04、光源とみなすしきい値の基準に下限 `SOURCE_T_FLOOR` 0.03（`harmonizer-prep.effect` の `SrcH`）。
  - 光源の光は掛け算をやめて、`base`（`hl` だけで暗くした色。基準の下限 `SOURCE_GAIN_MIN` 0.4）に足す。全体の分 0.6 → `SOURCE_AMB` 0.2、面の分 1.2 → `SOURCE_SIDE` 2.0。前景全体にも光源側ほど明るい傾き（`RAMP` 1.0）を付ける。
- これまでの夜（都市・自販機・夏の街・神社・秋の公園）と昼・夕方は、見比べてほぼ変わらないことを確認した。利用者の評価はまだ。
- 実機テストに「真っ暗な夜に小さな灯り」（`dark`）を追加した。旧版はここで落ちる（反対側が 0.69 倍までしか暗くならない）。

### 3.4 撮影処理の追加（色収差・周辺ボケ・グロー・レンズフレア・背景ぼかし）

きっかけは、動画編集ソフトでの「撮影処理」（アニメ絵にカメラで撮った質感を足す仕上げ）の紹介動画。5 つの工程のうち、4 つを入れた。

| 工程 | 実装 |
| --- | --- |
| 背景ぼかし | 新フィルター `obs_scene_relight_lensblur_filter`（`src/lensblur-filter.c`、`data/effects/lensblur.effect`）。背景ソースに掛ける |
| 目のハイライト | 自動化しない（キャラごとの手作業）。グローで「にじみ」だけ足せる |
| 色収差・周辺ボケ・グロー・レンズフレア | Finish（`finish.effect`、`finish-filter.c`）に追加。量の初期値は 0 |
| フィルム調の仕上げ | 既存のグレイン・ビネットに、色収差と周辺ボケを足して対応 |

参照実装（`tools/reference.py` の `finish()`、`lens_blur()`）とシェーダーは同じ式。`tests/headless_test.py` の 8・9 で、OBS の出力が参照実装と一致することを見ている（平均差 0.001 前後）。

設計の要点:

- **グロー**: 明るい所だけを 1/4 に縮め（画素ごとにしきい値を掛けてから平均）、1/8・1/16・1/32 と縮めながら、各段を 9 点ガウスでぼかす。4 段は `GlowMix` で、広がり（`glow_size`）が選ぶ段を中心にした重みで 1 枚に合成し、本体は 1 枚だけ読む。
- **周辺ボケ**: 画面全体を 1/4・1/8 に縮めてぼかし、周辺ほど混ぜる。色収差は、各チャンネルを放射方向にずらして読む（周辺ボケと併用でも、ずらした位置でそれぞれ混ぜる）。
- **レンズフレア**: 光源の位置を、光漏れと同じ「32x18 の平均の重心」にすると、複数の街灯の重心（灯りのない所）に付いてしまい、広く白い所（空・前景の白い服）にも引きずられた。そのため入力を 1/8 → 64x36 と「最も明るい画素」で縮め、`exp(-200 × 最大輝度との差)` の重みの重心を光源にした（`Peak8`・`Peak4`・`FlareStats`）。明るさの最大値が `smoothstep(0.5, 0.9)` を超えないとフレアは出ない。
- **背景ぼかし**: 線形光で、半径が 4 画素（`DISC_TARGET`）以下になるまで 1/2 ずつ縮め、64 点の円盤（黄金角のらせん）で平均し、3 次 B スプラインで拡大する。最後の拡大を双一次にすると、玉ボケの縁がブロック状になった。明るい点は `1 + 12 × bokeh × t²` の重みで玉ボケにする。

**OBS の仕様でつまずいた所（次に効く）**:

- **1 つのピクセルシェーダーで使えるテクスチャは 8 枚まで**（`GS_MAX_TEXTURES`）。超えると、毎フレーム `glBindTexture failed ... GL_INVALID_ENUM` が出て、見た目も壊れる。最初はグロー 4 段＋周辺ボケ 2 段＋統計 2 枚＋入力で 9 枚になっていた。グロー 4 段を先に 1 枚へ合成して 6 枚にした。**テストは、OBS のログに `error:` が出たら失敗にしてある**ので、ここで気づける。
- **エフェクトのパラメータは、technique を 1 つ描くたびに全部空に戻る**（`gs_technique_end`）。パスごとに、使う値を直前に設定すること。忘れると `Parameter 'xxx' set to invalid size 0, expected 4` が出る。
- 使わないテクスチャの枠にもダミー（1x1）を渡している。

**未確認**: Windows（D3D11）でのシェーダーのコンパイルと負荷。この環境の実機テストは Linux（Mesa llvmpipe の OpenGL）だけ。`PSFlareStats` は 64x36 = 2304 回の標本を 1 画素のシェーダーで回す（光漏れの統計は 576 回）。

用語や設定名は `data/locale/*.ini` の `Finish.*`、`LensBlur.*`。
